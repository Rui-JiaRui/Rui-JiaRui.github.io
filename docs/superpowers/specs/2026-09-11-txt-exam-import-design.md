# TXT 题库生成与结果页操作区优化设计

日期：2026-09-11

## 目标

提供一个本地 Node.js 命令，将固定格式的错题 TXT 转换为网站使用的 `paper.json` 和 `answer-key.json`，同时发布到 `data/exams/<试卷ID>/` 并更新 `data/registry.json`。修复结果页操作按钮在窄宽度下文字被逐字竖排、操作区过高的问题，同时保持现有视觉风格。

## 命令与文件范围

使用方式：

```bash
node scripts/import-exam-txt.js generate/20260801.txt
```

输入文件的基本文件名作为试卷 ID。上述命令写入：

```text
generate/20260801/paper.json
generate/20260801/answer-key.json
data/exams/20260801/paper.json
data/exams/20260801/answer-key.json
data/registry.json
```

转换器不生成或修改 `data/demo.js`。需要直接双击 `index.html` 预览新题库时，维护者仍可另行运行 `node scripts/generate-demo.js`。

默认将试卷 ID 加入 `data/registry.json` 中账号 `liurui` 的 `paperIds`。重复导入同一文件时覆盖同名 JSON，但不得在 `paperIds` 中产生重复项，也不得改变其他账号或其他试卷配置。

## TXT 格式

每道题由三块区域组成：

1. 题干和选项：第一行以 `【科目编号】` 开头，以全角括号题型标记结尾；随后是 `A.`、`B.` 等选项。
2. 答案解析：选项结束后、答案行之前的全部非结构化文本，允许空行和多行。
3. 答案行：以 `本题答案：` 开头，同时可包含首次作答记录。

每道新题固定由下一行 `【科目编号】...（题型）` 开始，上一题固定由 `本题答案：...` 行结束。允许 Windows 与 Unix 换行符，并忽略文件首尾及结构区域之间多余的空行。

支持的题型标记：

| TXT 标记 | JSON 类型 | 每题分值 | 每题时长 | ID 前缀 |
| --- | --- | ---: | ---: | --- |
| `（单选）` | `single` | 1 | 1 分钟 | `S` |
| `（多选）` | `multiple` | 2 | 2 分钟 | `M` |
| `（不定项）` | `indefinite` | 2 | 2 分钟 | `I` |

题目 ID 在各自题型内按出现顺序编号，例如 `S001`、`M001`、`I001`。选项 key 保持大写字母。答案中的连续字母拆分为数组，例如 `ABCD` 转换为 `["A", "B", "C", "D"]`。

答案行中的首次作答信息不是标准答案字段，原样附加在解析末尾；若解析和首次作答信息同时存在，以换行分隔。

## 元数据提取

- `paper.id`：输入 TXT 的基本文件名，例如 `20260801`。
- `paper.title`：`<试卷ID>错题回顾`。
- `paper.description`：从每题 `【科目编号】` 中提取编号前的科目名称，按首次出现顺序去重后使用中文顿号连接。
- `paper.durationMinutes`：所有题目的规则时长之和。
- `paper.totalScore`：所有题目的规则分值之和。
- `paper.showResultAfterSubmit`：`true`。
- `paper.hasAnswerKey`：`true`。
- `schemaVersion` 和答案 `version`：`1.0`。
- `questions[].tags`：包含从题号标记提取的科目名称。

题干保留完整首行，包括 `【科目编号】` 和题型标记，以保持与原始资料一致。解析中的自然段和逐项说明使用 `\n` 保留。

## 解析架构

转换器分为三个边界清晰的部分：

1. `parseExamText(text)`：纯函数，逐行状态机解析 TXT，返回标准化题目数据；不读写文件。
2. `buildExamFiles(paperId, questions)`：纯函数，根据题目生成 paper 和 answer-key 对象并计算元数据。
3. `publishExam(...)`：在全部解析和校验成功后，写入生成目录、发布目录并更新 registry。

文件写入必须发生在解析和完整校验之后。发布前先在内存中验证两个 JSON 对象，防止格式错误时留下部分生成文件。

## 校验与错误处理

以下情况视为错误并以非零状态退出：

- 输入文件不存在、扩展名不是 `.txt` 或文件名无法作为试卷 ID；
- 题目前缺少合法起始行；
- 题型不是三种支持类型之一；
- 一题少于两个选项或选项 key 重复；
- 缺少解析区或 `本题答案：` 行；
- 标准答案为空，或引用当前题目不存在的选项；
- 新题开始时上一题尚未由答案行闭合；
- `registry.json` 无法解析或找不到 `liurui` 账号。

错误信息包含输入文件路径和相关行号。任何校验错误均不得修改输出 JSON 或 registry。若目标文件已存在，成功导入时允许覆盖。

## 结果页 UI 修复

保持现有按钮颜色、字号、圆角和操作名称。桌面端操作区继续右对齐并允许整体换行；所有按钮文字设置为不可在汉字之间断行，并防止按钮被 flex 压缩到低于内容宽度。

移动端取消将结果页四个按钮强制变成纵向全宽模块，改为紧凑的可换行水平布局。空间不足时整颗按钮换到下一行，不允许“返回试卷”等文字在按钮内部逐字换行。筛选区域和历史记录布局不作其他视觉改版。

## 测试

新增转换器测试夹具，覆盖：

- 单选、多选、不定项解析；
- 三块区域和多题边界；
- Windows/Unix 换行、多余空行及多行解析；
- 题型对应分值、时长和 ID 前缀；
- 科目提取、去重和标题生成；
- 连续答案字母拆分为选项数组；
- 首次作答信息保留在解析中；
- 重复导入覆盖文件并对 registry 去重；
- 非法题型、缺少答案、错误选项和未闭合题目的失败行为；
- 解析失败时不修改已有输出和 registry；
- CSS 保证结果页按钮不拆字，移动端操作区采用可换行水平布局。

使用 `generate/20260801.txt` 进行端到端验证，并确认其输出能通过现有题库结构校验。

## 非目标

- 不提供浏览器内上传或编辑 TXT 的界面；
- 不支持自动识别没有题型标记或答案行的不规则文本；
- 不调用网络服务或大模型；
- 不把首次作答结果扩展为新的业务字段；
- 不自动更新 `data/demo.js`；
- 不重新设计结果页的整体视觉样式。
