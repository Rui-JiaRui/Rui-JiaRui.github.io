# 测试账号与手动题库导入优化设计

日期：2026-09-10

## 目标

将演示账号更新为 `liurui`，密码更新为 `K180`；提供结构清晰、可直接复制编辑的题目与答案 JSON 模板，并改进试卷选择页的信息展示，使维护者能快速确认手动导入结果。

## 范围

### 账号配置

- 更新 `data/registry.json` 中的账号和 SHA-256 密码哈希。
- 同步更新 `data/demo.js` 的本地文件预览回退账号。
- 更新登录页演示凭据提示及仅用于本地文件预览的密码兼容逻辑。
- 原账号 `student01` 不再作为演示账号使用。

### JSON 模板

在 `data/templates/` 下新增：

- `paper-template.json`：包含完整试卷元数据，以及单选、多选和不定项选择三种示例题。
- `answer-key-template.json`：按题目 ID 保存答案与解析，与公开题目内容分离。
- `README.md`：说明目录结构、字段含义、允许值、文件复制步骤和常见错误。

模板使用标准 JSON，不添加注释，确保可被浏览器和 JSON 校验工具直接读取。说明性内容仅放在 README 中。

### 试卷预览卡片

试卷选择页卡片显示：

- 试卷标题与试卷 ID；
- 总题数、时长和总分；
- 单选、多选、不定项题目数量；
- “已配置答案”或“待配置答案”状态。

答案状态由一个不含答案内容的发布字段 `paper.hasAnswerKey` 提供，避免在选择页提前加载答案文件。模板和现有样例题库都包含该字段。

## 数据流程

1. 维护者复制 `data/templates/` 中的模板。
2. 新建 `data/exams/<试卷ID>/`，分别保存为 `paper.json` 和可选的 `answer-key.json`。
3. 将试卷 ID 加入 `data/registry.json` 对应账号的 `paperIds`。
4. 若需要直接双击 `index.html` 预览演示数据，再同步更新 `data/demo.js`；正常静态服务器部署不需要此步骤。
5. 登录后在试卷选择页核对 ID、题量、题型统计和答案状态。

## 错误处理

- JSON 语法错误会导致该试卷加载失败，README 提供命令行校验方式。
- 题目 ID 必须在一套试卷内唯一；答案文件必须引用已存在的题目 ID。
- `hasAnswerKey` 只控制预览状态文字，实际交卷时仍以能否加载 `answer-key.json` 为准。
- 没有答案文件时，交卷结果不显示标准答案或解析。

## 验证

- 校验 `K180` 的 SHA-256 哈希与正式配置、本地回退配置一致。
- 使用 JavaScript 语法检查验证 `app.js` 和 `data/demo.js`。
- 使用 JSON 解析器验证账号配置、现有题库和新增模板。
- 检查模板题目 ID 唯一、题型合法、选项不少于两个，并检查答案均引用有效选项。
- 检查试卷卡片能生成题型统计和答案状态。

## 非目标

- 不增加网页上传、文件写入或浏览器内题库编辑功能。
- 不增加 CSV/XLSX 转换。
- 不改变静态站点的本地答卷保存与 HTML/JSON 导出机制。
