# 法考考试模拟网站：项目设计方案

版本：v0.3（固定题库文件与本地答卷保存方案）  
目标：仿照参考站点的“登录—匹配试卷—答题—交卷”流程。网站程序和所有题库均以固定文件部署；账号密码决定考生可进入的题库，提交后按题库内预设答案自动批改并展示解析。

## 1. 先确定产品边界

### 已确认的运行方式

做成一个可部署到任意静态托管服务的响应式网站，例如 GitHub Pages、Cloudflare Pages、Netlify、Nginx 或对象存储：

- 网站程序固定部署在根目录。
- 每个题库/试卷作为固定 JSON 文件放在 `data/exams/<试卷ID>/` 下，题目配图放在该目录的 `assets/` 下。
- 管理员在部署前，手动导入题库并生成/更新 JSON 文件、账号配置和题库索引；不在考生网页内提供上传入口。
- 考生先输入账号、密码；系统根据账号配置匹配到可进入的一套或多套题库。仅一套时直接开始，多套时显示选择页。
- 答题过程中自动保存进度，支持上一题/下一题、题号导航、标记、交卷确认和倒计时。
- 交卷后：有标准答案时自动批改并显示得分、对错、正确答案和解析；没有预设答案时只显示“已提交，暂未配置标准答案”，不输出答案和解析。
- 考生答案、开始时间和提交结果只保存在其浏览器 IndexedDB；刷新后可恢复，换设备或清除浏览器数据后不保留。

### 静态版的提交含义

在本方案中，“提交试卷”是结束答题、锁定本机答案并在当前浏览器中执行批改，**不会把答卷上传到网站管理员处**。静态托管不能接收或集中保存考生答卷。

若以后需要管理员看到所有考生的答卷、成绩、提交时间，或需要限制每个账号只能交卷一次，应增加一个很小的提交 API；答题页和题库文件结构无需重做。

### 必须提前知道的静态站点限制

纯静态前端无法真正保护以下信息：

- 题库中的标准答案和解析会被下载到浏览器，熟悉技术的用户可以查看。
- 账号、密码只能作为“页面访问门槛”，不能视为安全认证。
- 倒计时、交卷时间、成绩都可被用户修改；无法防止刷新、改本地数据或改浏览器时间。

因此密码匹配采用“使用体验上的入口控制”，不能被当作安全认证。实现上会把密码的哈希值而不是明文放入固定配置文件，同时将答案解析拆分为独立文件、只在交卷时加载，以减少普通用户误触或提前看到答案的机会；但有技术能力的用户仍可找到并查看静态文件。

产品保留两种可切换的部署模式：

1. **固定题库静态模式（本次实现）**：题库文件 + 浏览器 IndexedDB，适合个人练习、公开模拟、内网电脑和课堂演示。
2. **受控多人模式（后续可选）**：静态前端 + 后端或 Serverless API。答案只存服务器，登录、计时、提交和批改由服务器完成。

本次第一版是固定题库静态模式，不应宣传为防作弊或保密考试系统。

## 2. 角色与核心对象

### 角色

- **管理员/题库维护者**：在本机维护题库源文件、账号配置和答案解析，生成静态文件后部署网站。
- **考生**：登录试卷、完成答题、提交试卷、查看结果。

### 对象定义

运行时建议区分“题库源文件”和“发布试卷包”：

- **题库源文件 QuestionBank**：管理员维护的 JSON/CSV/XLSX 题目集合，可复用。
- **发布试卷包 ExamPackage**：部署到固定路径的一套题目快照、考试设置和可选答案解析。
- **账号映射 CredentialMapping**：账号、密码哈希和可进入的试卷 ID 列表。
- **考试记录 Attempt**：某个考生的一次答题和提交结果。

默认一个账号对应一套题库；数据结构允许一个账号对应多套题库，以便以后按班级或科目分组，无需改动登录页。

## 3. 页面与信息架构

```text
首页 /
├─ 账号、密码输入
├─ 考试须知与兼容性提示
└─ 匹配成功后进入题库选择或直接开始考试

考生端
├─ /                         账号密码登录
├─ /select                   多套题库选择（只有一套时跳过）
├─ /exam/:paperId           答题页
├─ /exam/:paperId/submit    交卷确认
└─ /result/:attemptId       成绩与解析

部署前维护工具（不部署给考生）
├─ tools/import-bank         导入/转换 JSON、CSV、XLSX
├─ tools/validate             校验题库、答案和图片路径
├─ tools/build-registry       生成账号与题库索引
└─ tools/preview              本地预览发布结果
```

## 4. 核心业务流程

### 管理员发布流程

```text
导入题库源文件 → 格式校验 → 设置考试参数、账号密码、答案解析
             → 生成 data/exams/<试卷ID>/ 固定文件 → 本地预览
             → 部署整个静态站点 → 考生访问
```

### 考生流程

```text
输入账号密码 → 系统匹配授权题库 → 选择题库（可选） → 阅读考试须知
             → 开始考试 → 答题、跳题、标记、自动保存 → 交卷确认
             → 自动批改/待批改 → 查看结果、答案、解析
```

### 状态机

发布试卷：`local_draft 本地草稿 → deployed 已部署 → retired 已下线`  
考试记录：`in_progress 进行中 → submitted 已提交 → graded 已批改` 或 `submitted_ungraded 已提交待批改`

## 5. 功能需求

### 5.1 登录与试卷选择

- 首页只显示账号、密码和考试须知，不预先公开所有题库。
- 凭据验证成功后，若账号有多套授权题库，显示试卷名称、简介、题量、总分和时长供选择；若仅有一套，则直接进入须知页。
- 试卷选择页保留参考站点“试卷一/试卷二”的直观卡片形式。
- 移动端单列卡片，电脑端两列或三列。
- 未映射给当前账号或已下线的试卷不可见。

### 5.2 账号登录与题库匹配

- 输入账号、密码后，在浏览器中计算密码哈希并匹配固定账号索引。
- 错误提示不区分“账号不存在”和“密码错误”，避免泄露信息。
- 可配置是否允许同一账号重复考试、是否允许恢复未提交记录。
- 默认不保存密码；仅在当前浏览器会话中保存已验证的账号与可访问试卷 ID。
- 静态版的“不可重复提交”只能限制同一浏览器中的记录，不能跨设备或阻止用户清除浏览器数据后再考。

建议登录策略：

- 账号只映射一套题库：验证成功后直接进入考试须知。
- 账号映射多套题库：验证成功后显示题库选择卡片。
- 账号被停用或题库路径加载失败：显示统一错误页，不暴露内部文件路径。

### 5.3 答题界面

电脑端建议采用“三段式”布局：

- 顶部：试卷标题、考生标识、剩余时间、交卷按钮。
- 左/中部：题干、材料、图片、选项和操作按钮。
- 右侧：题号导航，区分未答、已答、标记、当前题。

手机端建议采用：

- 顶部固定标题和倒计时。
- 题号导航改为可展开抽屉或底部面板。
- 底部固定“上一题 / 标记 / 下一题”，交卷按钮放在导航面板和顶部。
- 选项使用整行可点击卡片，增大触控区域，避免依赖小单选框。

必须支持：

- 上一题、下一题、直接跳题。
- 单选、多选、不定项选择三种题型。
- 标记题目、仅看未答题、答题进度。
- 自动保存当前答案和剩余状态。
- 离开页面或刷新后的恢复提示。
- 交卷前显示未答题数量和二次确认。
- 时间到自动交卷；本地模式需明确提示“计时基于本机时间”。

### 5.4 作答保存与恢复

纯静态网站使用浏览器 IndexedDB 保存答卷，不需要服务器：

- 第一次开始考试时创建唯一 `attemptId`，保存题库 ID、题库版本、账号标识、开始时间和截止时间。
- 每次选择或取消选项、切换题目、添加标记时立即保存；另外每 10 秒执行一次兜底保存。
- 保存考生答案、标记题目、当前题号、开始时间、截止时间和考试状态，不保存输入的明文密码。
- 刷新或重新打开同一浏览器时，如果存在 `in_progress` 记录，提示“继续上次考试”或“重新开始”。
- 不直接保存“剩余秒数”；根据固定的 `expiresAt` 重新计算，避免刷新页面使倒计时复位。
- 交卷时将状态原子地更新为 `submitted`，保存交卷时间、题库版本和答案快照，避免连续点击生成两份记录。
- 批改完成后保存总分、各题判定和批改所用的答案版本，并在“历史记录”中允许再次查看。
- 使用 `BroadcastChannel` 或页面锁避免同一浏览器同时打开两个标签页作答造成覆盖。

保存能力的边界：

- 同一设备、同一浏览器：可以自动恢复和查看历史答卷。
- 换浏览器、无痕模式、清除网站数据或更换设备：无法恢复。
- 网站管理员：不会自动收到这些答卷。

作为静态版的第二层备份，交卷结果页提供“导出答卷”按钮，下载一个 JSON 文件；文件包含题库 ID 和版本、账号标识、作答时间、考生答案及批改结果，不包含登录密码和整套标准答案。也可提供“导入答卷”功能，在另一台设备上查看已经完成的记录。

如果需要所有答卷自动保存到管理员处，网站页面仍可保持静态，只增加一个 Serverless 提交接口。交卷时前端向接口发送答卷，接口保存到 D1/Supabase/PostgreSQL；这是集中收卷、跨设备恢复和真正限制重复提交所必需的最小后端能力。

### 5.5 批改与结果

有标准答案时显示：

- 总分、得分率、答对/答错/未答数量。
- 按题查看：考生答案、正确答案、判定、解析、题目标签。
- 筛选：全部、答错、未答、已标记。
- 可选的“只看错题”复习模式。

没有预设标准答案时：

- 记录仍然可以提交和保存。
- 结果页显示“本试卷尚未配置标准答案，暂不计算成绩”。
- 不显示正确答案，也不显示解析，即使题目对象中存在空字符串字段。
- 管理员以后补充并重新部署答案文件后，考生可在原浏览器中对未清除的历史提交重新批改。

### 5.6 本地题库维护工具

- 该工具仅在管理员电脑上使用，不包含在公开网站的导航中。
- 新建、复制、编辑、发布、停用、删除本地试卷源文件。
- 读取 JSON；可选支持 CSV/XLSX 转换。
- 导入前预览，显示新增、覆盖、跳过和错误行。
- 题目顺序调整、批量改分值、批量设置标签。
- 单题编辑答案和解析。
- 试卷预览：以考生视角检查题目、图片、选项和移动端布局。
- 生成 `registry.json`、`paper.json` 和可选的 `answer-key.json`。
- 导出当前题库源文件和上一版发布目录作为备份。
- 静态模式不提供全体考生成绩后台；每位考生的考试记录只在其本机可见。

## 6. 题型和判分规则

第一版建议支持以下题型：

| 类型 | 标识 | 答案格式 | 默认判分 |
|---|---|---|---|
| 单项选择 | `single` | `['A']` | 正确答案固定为 1 个，完全匹配得分 |
| 多项选择 | `multiple` | `['A','C']` | 正确答案至少 2 个，选项集合完全匹配得分 |
| 不定项选择 | `indefinite` | `['B']` 或 `['A','C']` | 正确答案可以是 1 个或多个，选项集合完全匹配得分 |

交互上，单选使用单选按钮；多选和不定项选择均使用复选框。法考客观题默认采用“答案集合完全一致才得分”：少选、多选或错选均不得分，暂不启用部分得分。判分规则仍作为试卷配置项保留，避免写死在页面里。

## 7. 题库导入规范

### 推荐的发布目录

```text
site/
├─ index.html
├─ assets/                  网站公共资源
├─ data/
│  ├─ registry.json         账号、密码哈希与题库映射
│  └─ exams/
│     ├─ fa-2026-01/
│     │  ├─ paper.json      题目、选项和考试参数
│     │  ├─ answer-key.json 标准答案和解析（可选）
│     │  └─ assets/         该试卷的图片、附件
│     └─ fa-2026-02/
│        ├─ paper.json
│        └─ answer-key.json
└─ tools/                   本地维护工具，不部署给考生
```

题干与答案解析拆成两个文件。没有标准答案时不生成 `answer-key.json`，提交后只显示“暂未配置标准答案”，不显示答案和解析。

### 登录索引示例

`data/registry.json`：

```json
{
  "schemaVersion": "1.0",
  "accounts": [
    {
      "username": "student01",
      "passwordHash": "sha-256:...",
      "paperIds": ["fa-2026-01"],
      "enabled": true
    }
  ]
}
```

前端必须下载 `registry.json` 才能完成本地匹配，因此这不是安全认证；密码哈希只能避免直接保存明文密码，不能防止离线分析和修改网页代码。

### 推荐格式：JSON

```json
{
  "schemaVersion": "1.0",
  "paper": {
    "id": "fa-kao-2026-01",
    "title": "法考客观题模拟卷一",
    "description": "基础模拟练习",
    "durationMinutes": 120,
    "totalScore": 100,
    "shuffleQuestions": false,
    "shuffleOptions": false,
    "showResultAfterSubmit": true
  },
  "access": {
    "paperId": "fa-2026-01"
  },
  "questions": [
    {
      "id": "Q001",
      "type": "single",
      "order": 1,
      "score": 1,
      "stem": "题干文字……",
      "options": [
        {"key": "A", "text": "选项 A"},
        {"key": "B", "text": "选项 B"},
        {"key": "C", "text": "选项 C"},
        {"key": "D", "text": "选项 D"}
      ],
      "answer": ["B"],
      "analysis": "解析文字……",
      "tags": ["民法", "合同"]
    }
  ]
}
```

### 字段约定

- `answer` 可省略或为空数组，表示暂未配置答案；发布时更推荐将答案移入独立的 `answer-key.json`。
- `analysis` 可省略；有答案但没有解析时只显示答案。
- `stem`、选项文字支持 Markdown 子集；图片建议使用相对路径或随包导入的资源文件。
- `id` 在同一试卷内必须唯一；推荐使用稳定 ID，不要用行号作为唯一标识。
- `score` 必须为正数；没有填写时使用试卷默认分值。
- `source`、`year`、`subject`、`difficulty` 可作为扩展字段保留。

### CSV/XLSX 模板建议

列名：`id, type, order, score, stem, optionA, optionB, optionC, optionD, answer, analysis, tags`。  
多选和不定项选择的多个答案使用 `A|C`；标签使用 `民法|合同`。导入器需要提供模板下载和错误行定位。

### 导入校验

- 必须有题干、合法题型以及至少两个选项。
- 题号/ID 重复时报错，不静默覆盖。
- 单选答案只能有一个；多选答案至少有两个；不定项答案可以有一个或多个；所有答案都必须对应已有选项。
- 选项 key 不能重复；空选项给出警告。
- 分值、考试时长、总分必须是合法数字。
- 导入完成后显示统计：总题数、各题型数量、含答案数量、含解析数量、错误数量。

## 8. 数据模型

```text
QuestionBankSource
  id, name, description, version, sourceFile, questions[]

ExamPackage
  id, bankId, title, description, questionSnapshot[],
  durationMinutes, totalScore, shuffleQuestions, shuffleOptions,
  allowResume, allowRetake, resultPolicy, deployedPath, status

CredentialMapping
  username, passwordHash, paperIds[], enabled

Question
  id, type, stem, options[], score, answer?, analysis?, tags[], media[]

Attempt (静态模式下仅保存在考生浏览器)
  id, paperId, candidateId, startedAt, submittedAt, status,
  answers: {questionId, selectedKeys[], marked}[], score?, gradingVersion?
```

静态公开部署时不保存明文密码；标准答案拆分到单独文件，并且只在交卷后加载。这能改善正常使用流程，但不能对有技术能力的访问者保密。

## 9. 推荐技术方案

### 前端与发布

- Vue 3 + TypeScript + Vite：适合快速构建响应式 SPA。
- Vue Router：页面路由和考试状态守卫。
- Pinia：考试会话、计时器、答题状态。
- Dexie + IndexedDB：考试记录、答题进度和本机状态的本地持久化。
- SheetJS：CSV/XLSX 导入导出。
- CSS 变量 + 响应式布局；题目内容使用受限 Markdown 渲染，避免直接注入任意 HTML。

部署时上传编译后的静态目录即可。发布题库的固定流程为：

```text
导入/转换题库 → 校验 → 生成 data/registry.json
             → 生成 data/exams/<试卷ID>/paper.json
             → （有答案时）生成 answer-key.json
             → 本地预览 → 将网站和 data/ 一起上传
```

静态服务器必须允许读取 JSON 文件，并为 SPA 路由配置回退到 `index.html`。也可以使用 Hash 路由（如 `/#/exam/...`），从而无需服务器配置路由回退。

### 关键架构原则

把数据访问抽象为接口：

```text
Repository
├─ StaticFileRepository   读取固定 registry.json 和 exams/* 文件
├─ LocalAttemptRepository 本地 IndexedDB，保存答题和成绩
└─ ApiRepository          后续接入 HTTP API，集中提交和批改
```

这样可以先交付固定题库静态版，后续把登录、计时、提交和批改切换到后端，而不重写答题页面。

### 后端升级选项

若未来需要真正的多人考试，可采用 Supabase、Cloudflare Workers + D1、Node.js API 等方案。最低限度需要：管理员认证、考生认证、服务器时间、答案服务端批改、提交幂等和成绩查询权限。

## 10. 安全、隐私与合规

- 静态模式只适合低风险练习，不适合需要防作弊或保密答案的正式考试。
- 后端模式使用 Argon2/bcrypt 存储密码哈希，HTTPS 传输，答案服务端保存。
- 不在日志中记录明文密码、完整答案或不必要的考生信息。
- 题库可能涉及版权；导入和分享前确认题目来源和使用权限。
- 如果记录姓名、手机号或成绩，提前设计数据保留期限、导出和删除机制。

## 11. 非功能要求

- 适配宽度：手机 360px 起，平板 768px，电脑 1280px 以上。
- 题量目标：单卷至少支持 1,000 题；长题干和图片滚动不影响答题操作。
- 首屏加载尽量控制在 3 秒内；大题库按试卷或题目分页/懒加载。
- 浏览器优先支持最新版 Chrome、Edge、Safari；手机支持 iOS Safari 和 Android Chrome。
- 关键操作有键盘焦点、清晰颜色对比和触控反馈。
- 所有考试数据都有导出备份，导入失败不能破坏已有试卷。

## 12. 分阶段实施

### Phase 1：固定题库静态 MVP

1. 固定账号登录和题库映射。
2. 本地工具完成 JSON 导入、校验、预览和发布文件生成。
3. 单选、多选、不定项选择题答题页。
4. 倒计时、自动保存、题号导航、交卷。
5. 有答案自动批改；无答案显示待批改状态。
6. 电脑端和手机端适配。

### Phase 2：发布维护体验

1. CSV/XLSX 导入模板。
2. 本地维护工具中的单题编辑、批量改分、标签和搜索。
3. 试卷复制、版本管理、导出备份，一键生成 `data/` 目录。
4. 错题复习、结果筛选、历史记录导出为本机 JSON。

### Phase 3：多人和安全能力

1. 后端认证和服务端答案存储。
2. 多考生账号、考试次数和成绩统计。
3. 服务端计时、提交幂等、审计日志。
4. 管理员权限、题库共享和部署监控。

## 13. MVP 验收标准

- 生成一份包含 100 道题的发布包后，静态网站能显示准确题量和考试设置。
- `registry.json` 中的账号密码能匹配到正确题库；无权限账号不能进入该题库。
- 考生在电脑和手机宽度下都能完成答题、跳题、标记和交卷。
- 刷新页面后，已选答案和考试状态可以恢复。
- 关闭页面后使用同一浏览器再次打开，可以继续未提交考试；倒计时不会因刷新而重置。
- 配置答案的试卷交卷后能准确显示得分、考生答案、正确答案和解析。
- 未配置答案的试卷交卷后不显示答案、不显示解析，并保留提交记录。
- 时间到后能自动提交，重复点击交卷不会生成重复记录。
- 交卷记录能保存在本机历史中，并可导出为不含密码和完整标准答案的 JSON 文件。
- 发布文件错误不会覆盖上一版 `data/`；管理员可以导出并恢复上一版备份。

## 14. 建议采用的默认配置

- 题目顺序和选项顺序默认不打乱，便于和原题库核对；需要时再开启随机化。
- 多选题和不定项选择题默认答案集合完全一致才得分，不给部分分。
- 交卷后立即显示结果；无答案时显示待批改页。
- 默认开启自动保存和交卷前未答题提示。
- 默认允许恢复同一浏览器中的未完成考试，但不默认允许重复提交。
- 管理员先用 JSON 作为标准格式，CSV/XLSX 作为本地转换格式；题库更新后重新构建并上传静态文件。

## 15. 开始开发前需要确认的决策

1. 一个账号是否只对应一个题库，还是允许登录后选择多个题库？
2. 账号密码是“每套题库一组”，还是需要为每位考生生成独立账号？
3. 是否需要随机题目/随机选项？随机后是否允许复盘原题号？
4. 没有标准答案时，是否只显示“待批改”？
5. 是否需要把考生提交结果通过接口集中回传？如果不需要，成绩只保存在考生自己的浏览器。
6. 题目中的图片、表格、公式和富文本来源是什么格式？

如果没有额外决定，建议按“固定 `registry.json` + 固定 `data/exams/` 题库目录 + 浏览器本地提交记录”的方案进入下一步原型设计。
